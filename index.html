Core concept

Arrow functions

The idea

An arrow function is a value you can pass around. When it runs, it receives arguments and may return a result.

Remember this

An expression body returns its value. A block needs return when you want a result.

JavaScript fragment
const double = n => n * 2;const alsoDouble = n => { return n * 2; };const missingReturn = n => { n * 2; }; double(3); // 6missingReturn(3); // undefined
Part 1 of 3

An expression body returns the expression. With n = 3, n * 2 becomes 6.

This is a guided explanation. Run a full component in your course app using the linked exercise.

A small challenge

Write a function that adds 1 to a number. Show an expression body and a block body. Predict the result when the input is 4.

Show a hint

Keep the calculation the same. Only the block version needs the return keyword.

Compare with an answer
const addOne = n => n + 1;
const addOneBlock = n => { return n + 1; };
// Both return 5 when called with 4.

Both versions receive one number and return a new number. The braces change how you write the return, not the intended calculation.

Core concept

Map and lists

The idea

map calls a function once for each array item. It puts each returned value into a new array. Those values can be elements to display.

Remember this

Return an element for each item, and put a stable key on each returned sibling.

JavaScript + JSX fragments
// Component fragment; Text and View are imported.const names = ['Tea', 'Soup'];const rows = names.map(name => (  <Text key={name}>{name}</Text>));return <View>{rows}</View>;
Part 1 of 3

The callback receives one name at a time: first Tea, then Soup.

This is a guided explanation. Run a full component in your course app using the linked exercise.

A small challenge

Given [2, 5, 8], use map to add 1 to every number. Write both arrow-body styles. Predict the result and whether the original changes.

Show a hint

The callback receives one number. Its return value becomes one entry in the result.

Compare with an answer
const numbers = [2, 5, 8];
const result = numbers.map(n => n + 1);
const sameResult = numbers.map(n => { return n + 1; });
// Results: [3, 6, 9]. numbers remains [2, 5, 8].

This transformation creates a new array. Each callback returns a new number and does not mutate the input.

Core concept

Array state

The idea

State describes a render. To add an item, create a new array and ask React to use it in the next render.

Remember this

A setter accepts a new value or a pure updater function. Square brackets create the new array.

JavaScript fragment
// Inside an add-event handler; menu and setMenu already exist.const newItem = { id: 'b', name: 'Soup' };setMenu(previous => [...previous, newItem]); // Also valid using this render's menu:// setMenu([...menu, newItem]);
Part 1 of 3

Create the item outside the updater. In an app, assign a new stable ID when each item is created.

This is a guided explanation. Run a full component in your course app using the linked exercise.

A small challenge

Assume menu is array state and item is a new menu item. Write an add handler that appends item without changing the existing array.

Show a hint

Use a functional updater. Its parameter is the previous array, and it must return the next array.

Compare with an answer
const addItem = item => {
  setMenu(previous => [...previous, item]);
};
// Component-body fragment in JavaScript.
// In TypeScript, annotate item with MenuItem.

The updater receives previous queued state and returns a new array. Do not use push on the state array. Object braces would produce a different shape.

Core concept

Props and callbacks

The idea

Keep shared state in the parent. Give the child a function it can call to request a change. The parent updates state and passes new values down.

Remember this

Pass the function as a prop. Call it later, inside the event handler, with the expected argument.

JavaScript + JSX fragments
// Parent component fragments:const addItem = draft => {  setMenu(previous => [...previous, draft]);};<Composer onAdd={addItem} /> // Child JSX fragment:<Button title="Add"  onPress={() => onAdd({ name, popular })} />
Part 1 of 3

The parent owns menu and the callback. It passes the function itself to Composer through onAdd.

This is a guided explanation. Run a full component in your course app using the linked exercise.

A small challenge

Sketch a parent with menu state and a child with draft text. Write the callback prop and the child’s onPress expression. Explain who owns the array.

Show a hint

The child gets onAdd as a prop. Its press handler should call onAdd with a { name, popular } object.

Compare with an answer
// JavaScript + JSX example. E07 adds TypeScript types.
import { useState } from 'react';
import { Button, Switch, Text, TextInput, View } from 'react-native';

export default function Menu() {
  const [menu, setMenu] = useState([]);
  const addItem = draft => {
    setMenu(previous => [...previous, draft]);
  };
  return (
    <View>
      <Text>{menu.length} items</Text>
      <Composer onAdd={addItem} />
    </View>
  );
}

function Composer({ onAdd }) {
  const [name, setName] = useState('');
  const [popular, setPopular] = useState(false);
  return (
    <View>
      <TextInput value={name} onChangeText={setName} />
      <Switch value={popular} onValueChange={setPopular} />
      <Button title="Add"
        onPress={() => onAdd({ name, popular })} />
    </View>
  );
}

Menu owns the array. Composer owns the draft name and popular values, receives onAdd as a prop, and calls it on a press. The parent appends the draft with a pure updater, so the item count changes on the next render. This sketch isolates ownership and callback wiring; E07 adds TypeScript contracts, and the full app adds validation and stable IDs for rendered items.

Core concept

TypeScript inference

The idea

TypeScript can infer many types from values you supplied. Add a type when the starting value does not describe all the values you intend to store.

Remember this

Typed initial data guides inference. Empty arrays, null, and callback contracts often need explicit types.

TypeScript fragment; useState is imported
type Item = { name: string; popular: boolean };const initialItems: Item[] = [{ name: 'Tea', popular: false }]; // These hooks belong inside a component:const [menu, setMenu] = useState(initialItems);const [emptyMenu, setEmptyMenu] = useState<Item[]>([]);const [selected, setSelected] = useState<Item | null>(null);
Part 1 of 3

Item describes the object shape. initialItems already has the array type Item[].

This is a guided explanation. Run a full component in your course app using the linked exercise.

A small challenge

Define MenuItem with name and popular. Type an empty menu array and an onAdd callback prop that receives one MenuItem.

Show a hint

An array type is MenuItem[]. An action callback can have the type (item: MenuItem) => void.

Compare with an answer
type MenuItem = { name: string; popular: boolean };
type Props = { onAdd: (item: MenuItem) => void };

// Inside a component, with useState imported:
const [menu, setMenu] = useState<MenuItem[]>([]);

The state type tells TypeScript which elements may be added later. The prop type tells the child what argument to pass. void means the caller does not use the action callback’s return value.
