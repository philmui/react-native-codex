Menu builder rehearsal

Original 25-minute practice interview. The evaluator describes a menu screen with a title, a list of cards, and a child form that submits name and popular. These checkpoints and points are a self-study rubric, not an official course rubric. Start with the answer closed and a blank App.tsx.

  • Define a typed MenuItem array and show two initial items.
  • Render a custom ItemCard for each item using map and stable keys.
  • Build a controlled name input and popular control in a Composer child.
  • Pass an onAdd callback from the parent and append immutably.
  • Reject blank input and explain the complete event-to-render path.
  • If time remains, add removal or a popularity toggle.
Optional 25-minute pacing
  1. 0–3: Restate the requirements, draw App with Composer and ItemCard children, and identify who owns each state value.
  2. 3–7: Define the data type and initial state; render the list and inspect the map return.
  3. 7–12: Build the controlled input and child props type; describe the callback argument.
  4. 12–19: Wire the parent callback and immutable append. Test one valid and one blank submission.
  5. 19–23: Test duplicate names and explain why IDs, not names, are keys. Attempt one extension if the core works.
  6. 23–25: Explain direct versus functional setters and identify one limitation or next test.
Interviewer hints if the learner gets stuck
  • First prompt: What value must the map callback return?
  • Second prompt: Where is the menu state, and which function has access to its setter?
  • Third prompt: A valid append updater returns [...previous, item].

Study task list transfer rehearsal

Original 25-minute transfer interview. Build a study-task screen with title and done fields. The task should feel structurally familiar while changing names and behavior. Attempt it after the menu rehearsal without looking at the menu code.

  • Store Task[] in the parent with id, title, and done.
  • Render each task through a custom row with a visible completion label.
  • Let a child editor add nonblank task titles through a typed callback.
  • Toggle only the selected task through an immutable map update.
  • Display the number of unfinished tasks as a derived value.
  • Use a nested row/column layout with deliberate padding and spacing.
Optional 25-minute pacing
  1. 0–3: Sketch the component tree and list the state values versus derived values.
  2. 3–8: Create the type, seed data, and task rows. Explain stable identity.
  3. 8–14: Wire the child editor and parent add handler with a functional update.
  4. 14–19: Implement toggle by ID, copying the matching object.
  5. 19–23: Derive the unfinished count and test two independent tasks.
  6. 23–25: Explain why a shallow array copy alone would not protect an edited task object.
Interviewer hints if the learner gets stuck
  • First prompt: What should remain unchanged when only one task changes?
  • Second prompt: A row can receive an onToggle callback and call it with its ID.
  • Third prompt: Use previous.map with a conditional object spread.

Arrow functions

Q01 · What do n => n * 2 and n => { n * 2; } return for n = 5?

Hint

Name the two forms of function body.

Model answer

The expression body returns 10. The block body computes 10 but returns undefined because it has no return statement. Adding return inside the block makes the functions equivalent for this input. Parentheses around a multiline expression improve grouping but do not replace a required return in a block.

Follow-up

Rewrite both valid forms with the parameter type number.

Objects

Q02 · Why does () => ({ popular: true }) return an object?

Hint

The parentheses distinguish an expression from a statement block.

Model answer

After =>, a bare opening brace starts the function body. Wrapping { popular: true } in parentheses makes it an object expression, which the arrow returns implicitly. An equivalent block form is () => { return { popular: true }; }.

Follow-up

Write a function that receives name and returns { name, popular: false }.

map

Q03 · Given [2, 5, 8].map(n => n + 1), what is returned and what happens to the original?

Hint

Follow one input element at a time.

Model answer

The result is a new array [3, 6, 9]. The original remains [2, 5, 8] because this callback only computes values. map itself does not require mutation, but a callback can still mutate an object if written carelessly. For a normal dense array, each input element contributes one returned value.

Follow-up

What does map produce if its callback returns nothing?

JSX

Q04 · What is the difference between the braces in {items.map(...)} and the braces in item => { return ...; }?

Hint

The same character has different jobs in different positions.

Model answer

The JSX braces enter a JavaScript expression within markup. The arrow braces create a function statement block, where return is needed to supply a value. An object literal also uses braces. Debugging starts by identifying each brace’s role rather than treating all braces as interchangeable.

Follow-up

Name the roles of every delimiter in setItems(prev => [...prev, item]).

TypeScript inference

Q05 · Why can useState(initialItems) infer Item[], while useState([]) may need an explicit type?

Hint

Ask what information is available in each initial value.

Model answer

If initialItems is declared Item[], useState receives that evidence and infers the state type. An empty literal gives no element examples; in common strict React TypeScript settings useState([]) can infer never[]. useState<Item[]>([]) states the intended element type. Inference is useful, but it cannot guess all future values.

Follow-up

What annotation would you use for a selected item that initially has no value?

TypeScript boundaries

Q06 · Does type User = { name: string } guarantee a downloaded JSON object has a name?

Hint

Separate static checking from runtime execution.

Model answer

No. TypeScript’s type annotations are removed before execution and do not inspect downloaded values. A type assertion merely tells the compiler what to assume. Unknown external data needs runtime checks or validation before the app trusts its shape. This is a conceptual extension beyond the supplied Promise examples.

Follow-up

What simple check would you perform before reading an unknown value as a name?

State

Q07 · Why is let count = 0 inside a component insufficient for an interactive counter?

Hint

Consider both updating the screen and remembering a value.

Model answer

Changing an ordinary local variable does not ask React to render again. Also, the component function runs again on a later render and recreates the local initialization. useState retains a value across renders and provides a setter that schedules an update. A module-level variable survives calls but still does not notify React, and may be unintentionally shared.

Follow-up

What happens to a local variable if a parent causes the component to render again?

State snapshots

Q08 · Starting from count = 0, a handler calls setCount(count + 1) twice. What is the next count?

Hint

Both expressions read the same render’s count.

Model answer

The next count is 1. Each call asks for the value 1 computed from the captured zero. Two calls to setCount(c => c + 1) instead compose to 2 because each updater receives the pending result of the previous update. The current handler still reads its original snapshot after scheduling updates.

Follow-up

Predict setCount(5); setCount(c => c + 1) from an initial count of zero.

Setter forms

Q09 · Is setMenu(previous => [...previous, item]) valid? What is wrong with setMenu(previous => { ...previous, item })?

Hint

Keep the updater-function idea and inspect the returned value.

Model answer

It is valid and is useful when the next array depends on the previous array. A React setter accepts a next value or a pure updater function. The attempted code used braces and spread in an invalid block rather than returning a new array. Square brackets form the array; an expression body returns it automatically.

Follow-up

Show the equivalent block-body updater and the direct replacement form.

Immutable updates

Q10 · Is const next = [...items]; next[0].popular = true an immutable update?

Hint

What exactly was copied?

Model answer

The array was copied, but its objects are still shared. Changing next[0].popular mutates the same object referenced by items[0]. For a change to one item, use map and return { ...item, popular: true } for the matching item. Copy each level whose contents change. Unchanged objects may retain their references.

Follow-up

Why is [...items, newItem] sufficient when you are only appending?

Callbacks

Q11 · Explain onPress={save}, onPress={() => save()}, and onPress={save()}.

Hint

Distinguish a function value from the result of a call.

Model answer

The first passes save itself. The second passes a new function that calls save when pressed. The third calls save during rendering and supplies its return value as the prop, which is usually wrong. A wrapper is especially useful when passing a chosen argument, such as () => removeItem(item.id).

Follow-up

When can onChangeText={setName} be used directly?

Lifting state

Q12 · Two sibling components must display and change the same selected item. Where should the state live?

Hint

Locate their nearest common ancestor.

Model answer

Store it in their nearest common ancestor, pass the current selection down as props, and pass callbacks that request changes. This gives one source of truth. Keeping independent copies in each sibling creates a synchronization problem. State can remain local when no other component needs it.

Follow-up

Why might a form’s unsent draft stay in the form while submitted items live in the parent?

Function props

Q13 · Explain the type onAdd: (item: MenuItem) => void.

Hint

Read it as a contract for a value that is a function.

Model answer

onAdd is a property containing a function. The function accepts one MenuItem argument. Its caller does not use a returned result, represented by void. The parent supplies a compatible function; the child can call it with an object that includes all required MenuItem fields. The type declaration does not run the function.

Follow-up

How would the type change if the callback accepted only an item ID?

Controlled inputs

Q14 · The TextInput has value={name}, but typing does not update the display. What do you inspect?

Hint

Trace the input-to-state-to-prop loop.

Model answer

Check onChangeText and confirm it receives the new string and calls the setter for name. Verify the input’s value is not hard-coded or derived from another unchanged state. Also inspect whether an effect or parent update resets it. A controlled input displays its supplied value, so user edits must update the state that supplies that value.

Follow-up

Why is event.target.value usually the wrong expression for onChangeText?

Keys

Q15 · Why can an array index be a poor key for an editable or reorderable list?

Hint

A key identifies an item across renders, not merely its current position.

Model answer

If items are inserted, deleted, or reordered, the same index can refer to a different item. React may associate row state or focus with the wrong data. Use a stable unique ID stored with each item. Random keys are also poor because they force new identities every render. A key is not automatically passed as a normal child prop.

Follow-up

Where should key go when map returns a custom ItemCard?

Flexbox

Q16 · In a row container, what do justifyContent and alignItems control? What changes in a column?

Hint

Start by drawing the main axis.

Model answer

justifyContent distributes children along the main axis. In a row that axis is horizontal; in a column it is vertical. alignItems aligns children across the cross axis, which is perpendicular. React Native defaults to column, unlike the familiar web flex-direction default of row. The parent’s size must allow visible free space for distribution to be obvious.

Follow-up

Which container should receive these styles in a nested card layout?

Box model

Q17 · What is the difference between padding, margin, and borderWidth?

Hint

Trace from content outward.

Model answer

Padding creates space inside the border between the content and the edge. The border surrounds that padded content. Margin creates space outside the border between neighboring layout boxes. Use padding for a comfortable touchable interior and margin for spacing between cards. React Native style property names use camelCase and most numeric dimensions are logical units.

Follow-up

Why does margin not increase the interior of a card’s background?

Core components

Q18 · When would you use View, Text, Image, TextInput, and ScrollView?

Hint

Match each component to one job.

Model answer

View groups and lays out content. Text displays text and supports nested styled text. Image displays an image from a source and often needs explicit dimensions. TextInput gathers editable text, usually using state. ScrollView makes bounded content scrollable and renders its children together. For very large lists, FlatList is a useful extension because it renders a window of rows.

Follow-up

Why should arbitrary text not be placed directly inside View?

Modules

Q19 · What is wrong with import { Card } from "./Card" if Card.tsx exports default function Card()?

Hint

Braces indicate a named import.

Model answer

The module provides a default export, so use import Card from "./Card". The local name could also be MenuCard. Named exports use braces and match the exported name unless explicitly aliased. Type-only exports can be imported with import type. Package imports resolve installed dependencies; relative imports resolve local files.

Follow-up

Show a single statement importing a default Card and a named color.

Hooks

Q20 · Why should useState not be called inside an if statement?

Hint

React depends on consistent hook ordering between renders.

Model answer

If the condition changes, the component calls a different sequence of hooks. React can no longer associate each hook position with the same state or effect. Call hooks at the top level of a React function component or custom hook, before conditional returns. Place conditional behavior inside an effect or event handler instead of around the hook call.

Follow-up

How would you run an effect only while running is true without conditionally calling useEffect?

Effects

Q21 · Compare no dependency array, [], and [running] for useEffect.

Hint

Each case still involves setup after a committed render.

Model answer

Without a dependency array the effect runs after each commit of that component. With [], it is tied to mounting rather than changed reactive dependencies. With [running], it runs on mount and after commits where running changes. Cleanup runs before a replacement setup and on unmount. Development Strict Mode may add an extra setup-cleanup cycle, so [] is not a universal promise of exactly one call.

Follow-up

Why should every reactive value used by an effect be considered for its dependencies?

Timer cleanup

Q22 · Why does a counter accelerate after the user repeatedly opens and closes a screen?

Hint

Count how many intervals may still be alive.

Model answer

A likely cause is an interval created without cleanup, so old timers survive while new timers are added. Keep the interval ID inside an effect and return () => clearInterval(id). Also inspect whether a render body starts an interval on every render. A functional state updater avoids a separate stale-count problem, but it does not replace cleanup.

Follow-up

What does setSeconds(s => s + 1) solve, and what does clearInterval solve?

Promises

Q23 · What is logged by console.log("A"); Promise.resolve(2).then(n => console.log(n)); console.log("B")?

Hint

A fulfilled Promise’s then callback is still scheduled asynchronously.

Model answer

The order is A, B, 2. The synchronous statements finish before the Promise reaction runs. A Promise represents eventual fulfillment or rejection; then attaches a reaction and returns another Promise. Returning a value from a then callback passes it to the next stage; returning another Promise lets the chain wait for that Promise’s result.

Follow-up

What happens if a then callback uses braces but forgets return?

Cross-platform development

Q24 · What can be shared in a React Native app, and what must still be tested per platform?

Hint

Separate shared source code from runtime behavior.

Model answer

Components, state logic, TypeScript types, and much styling can be shared. Native controls, keyboard behavior, safe areas, permissions, text scaling, and library support can differ. Expo provides tooling and libraries around React Native; it does not remove the need for device testing. React Native is not simply a browser page packaged as a mobile app.

Follow-up

When might a custom native dependency require a development build rather than Expo Go?
